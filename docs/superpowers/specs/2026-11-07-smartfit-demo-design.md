# SmartFit 完整演示版设计

状态：用户已确认，按此设计实施。依据：SmartFit_SEEM5760_Final_Review.docx。

## 目标与边界

为课程展示提供可本地运行、可持久保存数据的响应式 Web 应用，覆盖消费者定制、社区、下单和履约流程。用户已选择完整演示版。应用默认中文，金额使用 HKD。文档属于需求来源，其中关于已完成系统、性能与商业效益的表述不视为实现结果。

演示版不发起真实扣款、短信、社交平台发帖或制造订单，不承诺真实合体预测或物理布料模拟。所有模拟服务在对应页面清晰标注。生产性能、安全合规认证和真实供应商可用性不属于验收结论。

## 方案与选择

1. 纯前端演示：部署简单，但无法验证服务端校验、订单快照与支付事件处理。
2. 完整本地演示（用户已选）：前后端真实交互和数据库持久化，第三方提供可替换演示适配器，适合课程演示。
3. 真实第三方集成：依赖九家服务的账户、权限、密钥及成本，留作后续。

## 架构与运行方式

沿用报告的 Vue.js、Vue Router、Vuex、Three.js、Node.js、Express、MySQL、Redis。使用 Vue 3 和 Vite 构建客户端。浏览器通过同源 /api 调用服务端。前端不接触服务端密钥。

开发者建议：默认采用 SQLite 持久化，降低本地运行门槛；同时提供 MySQL schema 作为后续迁移基础。首版不接通 MySQL 和 Redis，不提供双数据库切换。缓存和速率限制使用单进程内存实现。文档明确此项与报告架构的差异；演示版不宣称具备水平扩展能力。默认无外部 API 密钥也能运行。

外部服务统一通过服务端适配器返回规范化数据，并携带 demo/fallback 来源。首版九项外部集成都不需要联网；适配器边界、配置样例和后续接入说明应完整。代码不得把模拟结果标为已真实调用供应商。

## 页面和交互

- 首页：品牌介绍、手动城市选择、天气演示信息、至少三种面料推荐、精选款式及社区内容、搜索。定位仅在用户主动操作并同意时调用；拒绝或失败后仍支持城市选择。
- 定制工作室：左侧 Three.js 预览，右侧参数面板，包含裙装、上装，廓形、领型、袖型、衣长、面料、颜色、刺绣。展示报价，阻止不支持的组合，支持保存和再次打开设计。
- 身形面板：身高、胸围、腰围、臀围输入和范围校验；明确同意后才保存身体数据。模型比例随参数变化；标注为造型参考，不表示真实试衣结果。无 WebGL 时提供可交互的二维预览。
- 社区：分类筛选、搜索、帖子详情、点赞、评论、发布图片与可编辑文案、从帖子载入设计。文案由本地模板生成并标注；图片本地存储且检查大小、格式和文件内容，不标称使用 CDN。系统分享使用用户触发的浏览器分享或复制链接，不模拟 Facebook 授权成功。
- 我的设计：列表、打开编辑、创建订单、删除草稿；已下单的配置保留不可变订单快照。
- 结算：订单配置、金额、演示地址输入、身体数据同意提示和明确的模拟支付按钮；不收集银行卡信息。重复提交不得重复扣款或重复创建付款记录。
- 我的订单：订单列表、配置快照、状态历史、物流时间线。通过仅演示环境可用的操作推进生产、发货和签收，也可模拟支付失败。服务端验证状态转换。
- 附近服务：城市/区域筛选、演示地图或位置示意图、服务项目、距离与联系方式；明确区别演示 SmartFit 合作商和普通店铺。可用定位时按距离筛选 5 公里内数据，否则按手动区域展示。
- 账户：注册、登录、退出；可一键登录隔离的演示账户。设计、订单、个人数据接口均校验当前用户归属。访客可以浏览公共内容。

视觉由开发者决定：暖白、深色文字与鼠尾草绿强调色，时尚编辑式排版，适配桌面和手机，表单标签、焦点状态、错误反馈和加载状态完整。

## 数据、支付和隐私

实体包含 User、BodyMetric、Fabric、Design、Order、OrderDesignSnapshot、PaymentEvent、OrderStatusHistory、Shipment、TrackingEvent、SocialPost、Comment、Like、OfflinePartner。价格由服务端按目录和选项计算，以最小货币单位保存，客户端不可覆盖。

订单核心状态：pending_payment → paid → in_production → shipped → delivered；支付失败可重试，未付款订单可取消。演示支付结果由服务端演示适配器产生；事件具有唯一 ID 并事务处理，重复事件只处理一次。真实 Stripe webhook 未接入时不提供未校验的生产端点。履约推进接口仅在演示模式开放且校验订单归属；客户端不得直接设置任意状态。付款后修改原设计不得改变订单快照。

密码采用 bcrypt 哈希。认证使用服务端签名的短期凭据和 HttpOnly cookie，限制跨源请求与速率。输入验证、参数化 SQL、图片限制、文件名隔离、用户归属校验必须实现。身体数据需要明确同意，使用配置的密钥加密保存；提供用户数据导出及删除身体数据入口。支付和发帖不依赖可选天气或文案服务成功。示例账户与内容仅为虚构数据。

交付：frontend/ 与 backend/ 源码，种子数据，环境配置样例，数据库 schema，运行命令，中文 README，需求追踪表（已实现/演示/未实现），演示操作说明和测试记录。默认仅本地运行，不自动部署或发布。无需真实外部服务凭据。

## 可实施性审阅后的明确约定

- 一键体验每次创建独立演示用户，通过当前会话保持归属，不共享可编辑账户。
- 本地上传替代 Cloudinary；浏览器分享/复制链接替代 Facebook；应用内模拟通知记录替代 Twilio；其余供应商分别使用天气、搜索、文案、支付、物流与店铺演示适配器。
- 首次启动生成本地加密密钥并持久保存于 Git 忽略目录，支持通过环境变量替换；重启不应丢失解密能力。
- 已购买配置独立保存在订单快照中；删除设计不删除或破坏订单。支付失败保留 pending_payment，并单独记录失败事件；pending_payment 可转 cancelled。
- 上传仅支持解码校验通过的 JPEG、PNG、WebP，单图最多 5 MB；不接受 SVG 或远程任意 URL 下载。
- 实施前确定并在源码目录中定义服装兼容矩阵、身体尺寸范围及价目表，前后端以服务端规则为准，覆盖代表性合法与非法组合。
